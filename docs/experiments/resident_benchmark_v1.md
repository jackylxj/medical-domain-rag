# 常驻服务实验：2026-11-05

本次在 ModelScope NVIDIA A10 23,028 MiB 实例实际运行，非本地模拟。
Qwen2-7B-Instruct 使用 vLLM 0.27.1、BF16、eager 模式、上下文上限 2048、max-num-seqs=1。
BGE-large-zh-v1.5 在 CPU 常驻，4 个 PyTorch CPU 线程；Milvus Lite 持有现有 6 篇编写摘要、24 个片段的索引，COSINE Top-3。
网页由单 worker FastAPI 调用两个常驻服务，保留逐请求生成客户端子进程与结果落盘。

## 实验边界

- 无 Redis 或其他应用层答案缓存。vLLM 默认启用了前缀缓存，因此不能称为所有缓存均关闭。
- 服务端任务耗时不含服务启动、浏览器轮询或外部网络。它包含检索、生成客户端子进程和中间文件处理。
- 仅五次串行短问答，不报告 P95、并发吞吐或总体准确率。
- 旧版曾有一次 111.43 秒任务记录，但不是同一进程状态下的配对实验，不据此宣称严格加速倍数。
- 仍使用 base Qwen2 + v2 提示词。已知数字换算和冷冻蔬菜问题的错误拒答没有在本轮修复。

## 可复现材料

- `scripts/start_resident_cloud.sh`：启动三服务，设置当前镜像所需 CUDA 兼容库路径。
- `scripts/benchmark_resident_web.py`：固定五条问题，逐条保存任务响应。
- `outputs/resident_benchmark_v1/jobs.json` 与 `summary.json`：云端原始记录已下载本地；outputs 默认不进入源码版本控制。
- `docs/resident_services.md`：计时定义与启动说明。

在新目录重复运行：

```bash
python -m scripts.benchmark_resident_web --output outputs/resident_benchmark_v2
```

新运行若复用已经预热的进程，其首条请求不能等同于本轮的首次请求。
