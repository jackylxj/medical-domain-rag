# 第二轮候选开发题基线：执行与审阅规范

本实验使用已冻结的12条开发题（6可回答、3部分可回答、3资料不足），来自抑郁障碍、乙肝和儿童肺炎三个开发来源。题目由助手编写，不是独立专家金标准，也不是预留测试集。其余24条训练候选不进入本次推理。

## 控制变量

原始Qwen2-7B-Instruct与第一轮30k LoRA使用同一个vLLM引擎、基础模型、分词器、聊天模板、BF16及相同逐条输入。每题依次请求base和LoRA；仅请求中的模型名称不同。temperature=0、top_p=1、seed=42、repetition_penalty=1、max_tokens=512。不重新检索；直接使用已保存的证据。不给模型发送目标答案、样本类别、支持标注或缺失字段。

本次system和问题格式与新候选数据的导出格式一致，与旧v2/v3提示词不同，因此不能将此次结果与旧12题结果直接视作受控比较。服务命令、适配器哈希、模型配置哈希、分词器配置哈希和环境版本在云端运行记录中保留。

## 预定逐题审阅项

1. 有依据部分是否完整回答（6可回答题+3部分题）；若全拒答或漏掉已提供的关键子问题，记为未完整。
2. 资料不足部分是否明确说明缺失（3部分题+3资料不足题）；不能用模型背景知识补足。
3. 是否出现给定证据不支持的事实、数字、条件、诊断或建议；这是依据支持检查，不是判断常识是否正确。
4. 每个事实陈述是否有实际支持它的引用；编号存在不等于正确。纯缺失说明不强制引用。
5. 是否空答或因长度截断。

审阅由助手对照已冻结片段完成，不用同一个模型自动打分冒充独立评审。优先报告逐题原因与计数；12题不支持泛化医学准确率结论。请求耗时不作为冷启动或端到端性能对比。

## 执行

评估脚本 `scripts/evaluate_candidate_baseline.py` 连接同时列出 `medical-qwen2` 和 `medical-lora-30k` 的服务。输出目录必须尚不存在。

```bash
python -m scripts.evaluate_candidate_baseline --base-url http://127.0.0.1:8003/v1 --output outputs/evidence_candidate_baseline_v1
```

本轮单A10显存不足以同时运行两个7B服务，使用独立临时端口8003加载原模型和LoRA；原8001后端短暂停用，实验结束后恢复原启动参数。网页代码、检索、Redis配置不变。过程记录位于 outputs/baseline_run_control_v1。

## 实际结果（2026-11-05）

完成12题×2模型，共24次生成，无空答、无长度截断。两组逐题payload移除model字段后完全相同；证据相同。开发文件SHA256为 `2ec000c9e8c448533efe34f1d25e7f99eef92134b3d93861b375240e1dc64561`；30k适配器SHA256为 `2fa7cf3da30f6d9b0dc4ccc242d8e2c81b528f9d7b9db718d8308663a0200dfc`。

| 观察项 | 原始模型 | 30k LoRA |
|---|---:|---:|
| 含给定证据不支持的扩展（助手审阅） | 4/12 | 1/12 |
| 资料不足题仅说明缺失、未补充外部信息（助手审阅） | 1/3 | 2/3 |
| 有依据题/部分题提及要求的已知信息 | 9/9 | 9/9 |
| 上述回答另有自相矛盾的开头 | 1 | 0 |
| 含引用编号（机械检查，不等于引用完整） | 2/12 | 0/12 |
| 非法引用编号、空答、截断 | 均0 | 均0 |

“提及要求的信息”不代表整段回答正确。原始模型的pneumonia-03虽然提到脓和液体，却先说资料未提供具体描述，并追加输入未给出的剂量决定因素。它不能作为一条合格的完整回答。

明确越界的例子：两组hepatitis-04都给出了输入片段没有提供的疫苗首针“24小时”；原始模型depression-04先承认没有心理治疗频次，随后补出每周一次、两次等。原始模型pneumonia-01还扩展了未给出的机制和慢性疾病/免疫抑制治疗类别。此处标注的是相对输入的依据缺失，不是在断言这些外部信息本身必然错误。

12条逐题对照保存在私有输出 `outputs/evidence_candidate_baseline_v1/review.md`，原始响应在 answers.jsonl；公开审阅标注与回答哈希见 [review JSON](evidence_candidate_baseline_v1_review.json)。同一助手编写候选并审阅，存在评审偏差，需独立复核。

## 结论与下一步

这组开发题中LoRA的无依据扩展较少，但两组都没有稳定遵守引用要求。因此没有证据支持“第一轮训练整体坏了”，也没有证据支持“再训练原QA一轮就能解决引用问题”。它支持把第二轮目标明确为证据约束、部分回答、引用及未知信息边界。

本次使用候选数据中的简短system提示词，不能把引用失败完全归因于权重。下一步先固定这12题和证据，在两组模型上使用更明确的逐句引用/部分回答指令做一次受控开发对照；不改目标答案，不碰保留测试。若仍有稳定失败，再据此扩充独立事实单元并设计第二轮小规模SFT。避免直接用这24条重复事实训练后声称泛化提升。
