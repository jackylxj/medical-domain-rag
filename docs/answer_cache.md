# Redis 答案缓存

缓存匹配去除首尾空白后的完全相同问题，不进行语义相似匹配。不改变医学回答质量，也不会修复原模型的错误拒答。

## 配置与启动

云端安装 `redis-server`，在网页 Python 环境安装 `pip install -r requirements/cache.txt`。
确认旧网页进程已停止，再执行 `RAG_ENABLE_CACHE=1 bash scripts/start_resident_cloud.sh`。
脚本保留已监听端口；它不会给正在运行的网页进程自动添加缓存配置。也不要在初始化过程中重复执行。

Redis 仅监听 127.0.0.1:6379，128 MiB 上限，allkeys-lru 淘汰，关闭 RDB/AOF 持久化。
`RAG_REDIS_URL=redis://127.0.0.1:6379/0` 启用缓存；未设置时禁用。
`RAG_CACHE_TTL=3600` 为默认过期秒数。缓存只是加速层，Redis 不可用时记录 bypass_error 并继续正常问答。
依赖缺失属于部署错误；先安装客户端，运行时网络故障才会降级。

## 失效规则

缓存键包含：问题、当前网页进程部署 ID、生成后端与模型名/地址、检索进程实例 ID、知识库构建摘要 SHA256、检索配置，以及生成/提示词源文件摘要。
每次查缓存先读取常驻检索 health 以取得实际运行的版本；无法确认版本时绕过缓存。
知识库重建后必须重启检索服务；更换 Qwen 权重或后端部署后必须重启网页服务。不得在原地热替换权重后期待模型名自行变化。
网页重启会产生新的部署 ID，保守地使旧缓存失效。检索重启同样使旧缓存失效。
旧条目不会主动全库删除，最多一小时过期或被内存淘汰。

只缓存正常 stop 结束的非空回答，不缓存失败或长度截断。资料不足的正常回答也会缓存。
命中会保留答案、证据和原任务 ID，并明确 `generation_executed=false`；本次结果移除原 token 用量与生成耗时。
实际保存的回答与证据位于 Redis；缓存键哈希不等于内容加密。该演示不接收真实病历或个人隐私。

## 验证

使用 `python -m scripts.verify_answer_cache --output outputs/redis_cache_validation_v2`，目录必须不存在。
应在空缓存或新网页部署的空闲服务上运行。它测试三对问题、相同证据、不同问题不误命中、真实 Redis 一秒 TTL 过期、合成版本上下文变化、不可用 Redis 端口下的真实检索与生成降级。
版本测试使用合成字段，不声称实际换了一套模型或知识库。
每个任务记录 cache.status、来源任务与阶段计时。网页显示服务端任务耗时和是否复用缓存，浏览器实际等待还包括网络与轮询。
